agentops-stacks · databricks-solutions

One agent, three workspaces, every promotion gated on evals

Scaffold an agent with agentops-stacks and promote it dev → staging → prod. Each step passes CI checks and an LLM-judged eval gate, and service principals deploy staging and prod. This guide shows how to demo it on your own deployment, with a talk track for each part.

Live links are off until you connect your deployment. One prompt to your coding agent does it.

Staged red gate

optional · set up the day before
  1. Make a branch that removes the SYSTEM_PROMPT guardrail from graph.py, and open a PR. Don't merge it.
  2. CI compares against the staging champion, so a large enough safety drop fails eval_gate and the merge button stays blocked. The failed run also shows up in staging evaluation runs.
  3. The result is probabilistic. In the reference run, the agent without its guardrail scored 0.95 (one of 20 flagged). That fails with zero tolerance, but passes once the 0.05 safety tolerance from #81 is in. Only show it if it went red. Close the PR afterwards.

Risks and fallbacks

8 known
If this happensDo this
A link says "set up"Your agent didn't find that value. Hover the link to see which, or check Setup.
CI/CD sits in the queueNo runner picked it up. Check Actions is enabled for the repo and, for a self-hosted runner, that it's online. Or show your recorded green runs.
A live link stops at a login pageSign in to that workspace in the browser you present from. Each workspace has its own session.
App URL returns 503 in the browserNo chat UI is scaffolded (#59). Have your agent call the App, which uses /invocations.
A gate turns red on a judge flakeWithout a tolerance, block tier allows zero regression against a 1.00 champion (#84). Rerun the job and say the gate is strict on purpose.
Live scaffold differs from your repobundle init pulls upstream main, which may have moved. Show your first commit instead.
Your agent can't reach a workspaceIts CLI login expired. Run databricks auth login for that workspace's profile.
Someone asks for your repo linkIf it's private, keep it to screen-share and point them to the BBAOps tab's public links.

Q&A cheat sheet

5 likely questions
Is it production-ready?
It's ready as a pattern. As a template it still has open issues upstream, with fix PRs in flight. The most important is #70: the eval gate passes when nothing was scored, fixed in #81.
Can it do multi-agent?
Yes. add-supervisor scaffolds a supervisor. Its sub-agents are stubs that you wire up yourself.
Where do traces live?
In each env's MLflow experiment (prod traces). Artifacts go to a UC volume declared in the bundle.
How do you attribute cost?
With project / env / agent tags and an optional serverless usage policy, queried from system.billing.usage. The usage-tracking-ops skill sets it up.
What credentials does CI hold?
One OAuth M2M secret per env service principal, stored in GitHub secrets. Each SP can manage only its own env's catalog. Show the prod SP.

Setup

Connect your deployment

The guide's live links open your own dev, staging and prod workspaces. Your coding agent finds the values and saves them in a small file next to this page, so there's nothing to fill in.

One prompt, then reload

run it from your project

Do this once dev, staging and prod are deployed. Then reload this page.

Create demo-guide-config.js in the same folder as agentops-stacks-demo-guide.html. It should set window.DEMO_GUIDE_CONFIG to an object with values from my agentops-stacks project and its dev, staging and prod deployments:

- repo: GitHub owner/name
- project: bundle name
- agent: agent name (the folder under src/agents/)
- endpoint: the agent's LLM endpoint
- dev, staging, prod: one object each with
  - host: workspace URL
  - catalog, schema: where the bundle deployed (dev's schema has the dev-mode prefix)
  - app: App name
  - tracesExp: ID of the experiment attached to the App
  - evalExp: ID of the /Shared/<project>_<agent>_eval experiment
  - job: ID of the eval dataset job, if there is one
  - sp: numeric ID of the service principal that created the App (empty for dev)
  - files: workspace object ID of the deployed bundle files folder

Only read from the workspaces; don't change anything. Use an empty string for anything you can't find. bundle summary only resolves staging and prod as their deploy service principal, so read those targets from the deployed App instead.

The values live in demo-guide-config.js, next to this file. Leave it out when you share the guide, and add it to .gitignore if the guide lives in a repo.

Install the plugin

from the plugin README

Claude Code or Cursor

Clone the repo, then run the installer from your target project's root.

git clone https://github.com/databricks-solutions/agentops-stacks.git
cd <your-project>
/path/to/agentops-stacks/plugin/skills/install_skills.sh

Then type /init-agentops-stacks or say "scaffold a new agentops-stacks project."

Keep the clone. The installer copies only each SKILL.md, and add-agent / add-supervisor call scripts that live in the clone (#49).

Genie Code

Install into your workspace from a local clone:

git clone https://github.com/databricks-solutions/agentops-stacks.git
cd agentops-stacks
./plugin/skills/install_skills.sh --install-to-genie --profile <your-profile>

No local shell? Run install_genie_code_skills.py as a notebook. Then open Genie Code inside a Git folder and say "scaffold a new agentops-stacks project."

Prerequisite for the post-scaffold skills: ai-dev-kit.
